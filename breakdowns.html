The traces stay up because they show what the pipeline called and what the robot actually did. Every step is one sub-module of the pipeline with the function / tool calls it made (names only — hover a call for what it does and where it lives), a description of the step, and the resulting trajectory. The step descriptions are not a machine log: they are the project's own explanation of each step, written when the runs were captured, before the audit, with each run's numbers and log lines filled in. They are shown as captured; where the audit contradicts a step, the step carries a red Audit line, and that line overrides the description.

Calls: function ↳ internal sub-call inline block in the co-sim script subprocess external model · click a step to expand its description and jump the plot to its moment (steps from earlier attempts have no moment on the final-episode plot).
Plot: drag to orbit · wheel to zoom · shift-drag to pan · scrub the timeline. In the in-hand spin case the wrist reference is frozen by design and only the object reference rotates; the wrist stays put, so any movement of the object path there is the object moving in the grip. The red strip under each plot is |wrist−object| over time, so a rigid hold reads flat and a slip, a drop or a turn in the hand shows as a change.
