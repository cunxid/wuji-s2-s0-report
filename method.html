Method — the S2 skill codebase

What code decides where we probe, how a probe runs, and how a result becomes knowledge. Source of truth: s2/harness/ on branch jd/mixed-s0-s2 of the training repo.

What decides WHERE we probe

1. Campaign grids (campaigns.py, campaigns_gpu.py): each campaign is a deterministic job list over one boundary axis (or one interaction pair), organised by the four boundary classes of the proposal — preconditions (yaw, noise, workspace, lift height), motion envelopes (carry direction×speed, spin angle×speed, wrist axis×angle, palm tilt), contacts (elevated place, guarded press), and sequences. Coarse CPU grids first (30°, 3–4 levels), dense GPU refinement second (5°, full matrices).

2. The V2 functional index (campaigns._h_verbs): the Atlas key is (object, hold-state, verb, params) — the hold is the latent variable that sets every envelope, so verbs are probed FROM each hold (default grasp vs recorded regrip holds), reached by validated prefixes. make_dashboard._stage classifies each failure as prefix | verb | tail from the phase timeline, so acquire failures never pollute a verb map.

3. Hypothesis probes: when a failure pattern suggests a mechanism, the next campaign is the minimal discriminating experiment — D-REPAIR (refuted the yaw-band re-pick hypothesis), D-COMPOSE (4×90° composition), U-REPAIR → U-REPAIR2 (the unseen-object repair ladder: env change → reduced post-grasp demands).

4. Fairness rules: programs for realistic tasks are the verified demos', untouched; success is the project's validated action_at criteria; every cell records its execution route (gated CPU vs open-loop GPU) because grasp success is protocol-coupled; failures are published alongside successes.

How a probe runs

CPU closed-loop route: run_campaign.py (resumable pool) → one worker.py subprocess per job → settle the scene (s1 settle()) → S1 EpisodeRunner (deploy observation proxy, runtime gates, drop detection) → metrics.py (tracking error, in-hand twist via quaternion twist decomposition, slip, phase events) → metrics.json.

GPU open-loop route: clipgen.py compiles each job's program into a synthetic Forge clip (the 5 trajectory-reader arrays), injects it into the local v21 release with SHA256 manifest appends; gpu_batch.py runs one CUDA env per probe through the stock WH120 eval path (hand-table patch applied), shards sized to shared-GPU memory, and extracts per-env outcomes from recorded series.

How a result becomes knowledge

analyze.py applies per-campaign success rules (success()) and writes the Capability Atlas (s2/atlas/, one JSON per object: feasibility cells with params, route, failure mode, metrics, run pointers). Durable rules are distilled into s2/skills/*.md cards (s1/ASPIRE format: when / numbered rules / not-limits) and s2/primitives/*.json (validated envelopes per bimanual role). make_dashboard.py renders everything you see here; publish_report.sh ships it.

Known gaps, by design: grids are pre-declared (no active sampling yet — bisection and edge replication are the planned upgrade); one placement per cell (deterministic sim); hold-state reached by prefix rather than snapshot-init.
