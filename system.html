The S2 system — what it is, the calling flow, and a self-contained menu of every part

Companion to SR_API.md (verb contracts) and README.md (file map). This is the OPERATIONAL view: how an S2/SR agent runs the loop scene → sub-task → tool calls → retry on S0-wrapper returns, and what each stage consumes/produces, with the exact code entry points.

1. What the system is

Five planes over one frozen policy (AUTO3 Mixed model_8000.pt, Object-only — never retrained):

plane role artifacts / code
Knowledge what S0 can do, per (object, hold, verb, params) atlas/*.json (2,000 route-tagged cells), skills/*.md rule cards, primitives/*.json envelopes, SR_API.md
Decision task → verb chain + feasibility checks + repairs task cards (SR_API.md §task cards), repair ladders (validated in U-/V-REPAIR campaigns)
Generation verbs → 50 Hz wrist+object reference harness/api.py builders → program IR → harness/sr_api.py (stream: 24 ms first chunk)
Execution the S0 wrappers gated closed-loop: s1 EpisodeRunner/S0Episode (deploy-faithful); open-loop vectorized: harness/gpu_batch.py (probing only — acquire needs the gate off-distribution)
Evaluation wrapper returns → typed outcome harness/metrics.py, s1 evaluate_task (action_at criteria), analyze.success() + make_dashboard._stage()

The same five planes serve two drivers: the explorer (campaign grids that FILL the Atlas — how all knowledge here was produced) and the runtime SR (which READS the Atlas to act). The loop below is the runtime view; the explorer is the same loop with a grid instead of a task.

3. The menu — each part self-contained

[A] Perceive & anchor

  • Purpose: turn raw scene into the canonical scene dict (p1_scene_v1).
  • Inputs: object key, observed pose, fixtures. Outputs: {"object": {key, pose}, "fixtures": [...]}.
  • Code: api.scene / yawed_pose / block_fixture; s1 settle() (cached in sr_api.SRSession.settled).
  • Must know (Atlas): pose-observation tolerance of the next acquire (≈2–3 cm / ~10°); if the estimate is worse, plan an align_actual or get a better observation first.
  • Failure signals handled here: none (upstream of S0).

[B] Decompose — sub-task generation

  • Purpose: task → ordered verb chain with parameters, each step pre-checked against the Atlas.
  • Inputs: task intent + scene + Atlas. Outputs: verb chain (task card instance).
  • Code/data: task cards in SR_API.md; Atlas lookups = read atlas/<object>.json cells filtered by (hold, skill, params, route); distilled shortcuts in skills/*.md, envelopes in primitives/*.json.
  • The queries per verb (full table in SR_API.md): pick band & protocol for acquire; verified-route holds for regrip; per-direction speed for transport; signed angle×speed per hold for spin; axis×angle for wrist; tilt band for hold; scatter-vs-tolerance for any A→B sequence.
  • Hard rules baked in: acquire is GATED by default (open-loop acquire ≈0 off-distribution); re-observe across every place/release; compose long motions from envelope interior; align_actual before any precision contact; hold-state chosen BEFORE verb parameters (it sets every envelope).
  • If a step is infeasible: insert a repair at decomposition time — regrip to a verified hold (screwdriver), environment change (overhang/pocket for flats/spheres), split the motion (4×90°), or route the rotation through a different mechanism (spin vs wrist vs table support).

[C] Emit program

  • Purpose: verb chain → the task-program IR (p1_task_program_v1).
  • Inputs: verb chain. Outputs: program dict (steps + runtime gates).
  • Code: api.program / prog_pick_hold / prog_carry / prog_spin / prog_wrist_reorient / prog_guarded_press / prog_hover_align / prog_handoff_present / _h_verbs-style regrip steps; validation = s1 validate_program (IR caps: 0.6 m/s, 240°/s, |spin| ≤ 2200°, lift ≤ 0.35 m — a compiler rejection is itself a boundary datum).
  • Gotchas: lift must follow grasp; regrip must follow a lift; place restores grasp-time wrist orientation but keeps in-hand θ; omit palm_normal_z unless the object's Atlas entry says otherwise.

[D] Generate the reference (the fast path)

  • Purpose: program + scene → the 4 arrays S0 consumes (wrist/object pose, qpos+links placeholders).
  • Inputs: program, scene. Outputs: full arrays or streamed segments.
  • Code: sr_api.SRSession — .reference() (167–324 ms warm incl. long programs) and .reference_stream() (first chunk ≈24 ms, covers S0's 40-frame lookahead; remainder compiles ~100× faster than execution). Session preload ≈0.2 s/object; settle cached per quantized pose.
  • Contract with [E]: segments overlap by one frame and must be continuous (the episode's commit() checks); reference must always stay ≥0.8 s ahead of the cursor.

[E] Call the S0 wrapper

  • Purpose: execute, with the runtime's closed-loop protections.
  • Inputs: first segment + stream. Outputs: per-tick summaries, events, final report + trace.
  • Code: production-faithful = s1 harness/episode.py EpisodeRunner → sim_backend.S0Episode (one episode per process; gates: reference held until lift_confirmed; slip pause; drop abort; align_actual/approach_until_stop implemented here). Batch probing = harness/worker.py (CPU) or harness/gpu_batch.py (open-loop, no gates — use only for cells verified on that route).
  • What the wrapper returns, live: events.jsonl — phase, gate_wait_lift/gate_open, lift_confirmed, drop, slip_pause/resume, grasp_timeout, approach_stopped, align_actual records, finish(reason); per-tick summary() — object/wrist pose, palm-relative pose, contacts, lowest-z, margin frames.

[F] Read the returns — typed outcome

  • Purpose: wrapper output → a decision-grade verdict.
  • Inputs: run dir (trace.npz, report.json, events.jsonl). Outputs: outcome record.
  • Code: harness/metrics.py compute() (lifted/drop ticks, tracking p50/p95, slip, in-hand twist via quaternion twist decomposition, per-phase twist, finish reason); task-level truth = s1 evaluate_task(run, criteria.json) (action_at — AUTHORITATIVE over the generic drop flag: the bulb seat-press false positive); analyze.success() per-campaign rules; make_dashboard._stage() → prefix | verb | tail (which stage actually failed).
  • Verdict vocabulary: no_lift / drop(stage, held_s) / overshoot / slip / stuck / program_rejected / diverged / criteria{id: ok}.

[G] Commit effects (success path)

  • Purpose: update believed state and continue the chain.
  • Rules from data: place leaves the object 1–3 cm off with release drag and the kept θ — so the believed pose after place/release is only a PRIOR; any following acquire or precision contact must re-observe (align_actual, or recompile the tail from the measured pose — open-loop recompilation cannot cross a place/release boundary).

[H] Retry ladder (failure path, keyed by stage — every rung validated by a campaign)

  • prefix/acquire failed (no_lift, grasp_timeout):
  • slow close / longer approach (T_close_s, T_approach_s — U-REPAIR),
  • different in-band yaw or the other resting face (A-YAW/V-GRASP bands),
  • flipped side / heading override,
  • environment repair: block overhang for flats, pocket for small round (U-/V-REPAIR: converts no_lift → real holds; completes for ≥10–12 mm-thick elongated objects),
  • gated protocol if it wasn't (hammer: 73% gated vs 18% open-loop),
  • else: outside envelope → replan task or mark for S0 training coverage.
  • verb failed (drop during the verb):
  • shrink into the envelope interior + pauses (D-COMPOSE: 4×(+90°) works where +360° drops),
  • change hold via a VERIFIED regrip route (H-SCREW: 3/16 → 18/19),
  • reduce post-grasp demands (low lift + quick place — U-REPAIR2),
  • per-object tilt from the B-PALM band; never transfer tilt across objects,
  • route the motion differently (wrist instead of spin, or table support instead of wrist).
  • tail failed (during place/release): check task criteria first (may already be a pass); else re-observe and re-place; for standing objects use fast retreat (skill card).
  • sequence failed: insert re-observation between the steps; verify effects(A) ⊆ preconditions(B) numerically before retrying.
  • Retry mechanics: every retry is a fresh episode (episode-per-process contract); deterministic sim means an unchanged retry reproduces the failure — a retry must change protocol, parameters, hold, or world.

4. Where each claim comes from

Every rule above carries a campaign tag (A/B/C/D/E/F/G/H-, T-TASKS, T5, U-, V-*) — raw cells in atlas/, runs under s2/runs/<campaign>/<job>/, narrative in reports/REPORT.md, rendered at https://cunxid.github.io/wuji-s2-s0-report/.
